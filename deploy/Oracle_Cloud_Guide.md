> هذا الدليل مرجع تنفيذي مرتّب بالخطوات. كل خطوة مرفقة بـ«ماذا تفعل» و«كيف تتأكد أنها نجحت».
>
> ⚠️ **ملاحظة (محدّثة):** قد يرفض Oracle فتح صفحة التسجيل من بعض الشبكات (فحص امتثال تصدير يعتمد على IP). إن حدث ذلك راجع **`deploy/Azure_Cloud_Guide.md`** — حزمة النشر نفسها تعمل على أي خادم Ubuntu.

## المرحلة 2 — إنشاء الخادم (Instance)

من **Console → Compute → Instances → Create instance**:

| الحقل | القيمة الموصى بها |
|-------|-------------------|
| **Name** | `mrw-bot` |
| **Image** | `Canonical Ubuntu 22.04` (يدعم ARM) أو `Oracle Linux 9` |
| **Shape** | `VM.Standard.A1.Flex` → 4 OCPU / 24GB RAM ← **الاختيار الأمثل** |
| | (إن ظهر خطأ *Out of capacity* → جرّب Shape آخر أو منطقة أخرى أو أعد المحاولة لاحقًا — المشكلة سعة لا خطأ منك) |
| **Networking** | أنشئ VCN جديدًا + Subnet عام + **Public IPv4** (مفعّل) |
| **SSH keys** | `Generate key pair for me` باسم **`mrw-key`** ← **نزّل المفتاح الخاص** (`.pem`) فورًا — لا يمكن استرجاعه بعدًا |
| **Boot volume** | `Custom size` = **100GB** (داخل الحد المجاني 200GB) |

**تثبيت IP ثابت (مهم):**
بعد إنشاء الخادم: `Instance → Create reserved public IP` — لأن الـ IP الافتراضي **ephemeral** يتغير عند إيقاف/تشغيل الخادم.

## المرحلة 3 — النشر

### 3.1 الاتصال الأول
```powershell
ssh -i "$HOME\Downloads\mrw-key.pem" ubuntu@<IP_الخادم>
```
> اسم المستخدم: `ubuntu` لـ Ubuntu، و`opc` لـ Oracle Linux.
> إذا ظهر خطأ `UNPROTECTED PRIVATE KEY FILE` (ويندوز):
> ```powershell
> icacls "$HOME\Downloads\mrw-key.pem" /inheritance:r /grant:r "$($env:USERNAME):R"
> ```

### 3.2 رفع المشروع وتشغيل التثبيت (أمر واحد من ويندوز)
```powershell
cd "<مسار المشروع>"
.\deploy\deploy_from_windows.ps1 -ServerIP <IP_الخادم> -KeyPath "$HOME\Downloads\mrw-key.pem"
```
السكربت: ينسخ المشروع (بدون `.venv` وبدون **جلسة حسابك الشخصي**) ← يرفعه ← يشغّل `install.sh` الذي:
يثبّت بايثون وبيئات وudevirt، ينشئ swap، ينشئ مستخدم `mrw`، يثبّت خدمة systemd مع **إعادة تشغيل تلقائية** عند التعطل، يضبط جدار الحماية على SSH فقط، ويشغّل **مؤقّت النشاط** (حماية من استرداد Oracle للنسخة الخاملة).

### 3.3 إدخال المفاتيح السرّية
```bash
nano /opt/mrw-bot/.env
```
```env
BOT_TOKEN=1234567890:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
ADMIN_IDS=1557513643
LOCAL_UTC_OFFSET=3
```
```bash
sudo systemctl restart mrw-bot
```

## المرحلة 4 — التحقق والتشغيل

```bash
systemctl status mrw-bot          # يجب أن يظهر: active (running)
journalctl -u mrw-bot -f          # السجلات المباشرة
```

**اختبار حقيقي:** افتح البوت `@blgh_bot` من حسابك واضغط `/start`، ثم أرسل صورة ورابطًا ووصفًا — يجب أن يصل إشعار بالبلاغ فورًا.

> ⚠️ **مهم:** أوقف نسخة البوت الموجودة على جهازك ويندوز قبل التشغيل على الخادم، وإلا حدث تعارض `409 Conflict` (مستدعِيان يقرآن التحديثات معًا) وتوقّف الاثنان.
> ```powershell
> # إيقاف البوت المحلي
> Get-Process python | Where-Object { $_.Path -like "*المخالفات*" } | Stop-Process -Force
> ```

## المرحلة 5 — الحماية والمتابعة

| المهمة | الأمر / المكان |
|--------|---------------|
| فحص حالة الخدمة | `systemctl status mrw-bot` |
| سجل الأخطاء | `journalctl -u mrw-bot -p err --since today` |
| مساحة القرص | `df -h` |
| منفذ مفتوح | `ss -tlnp` (يجب أن يظهر 22 فقط) |
| **متابعة التكلفة** | Console → **Cost Analysis** — يجب أن يبقى usage ضمن Always Free |
| **حماية من الاسترداد** | مؤقّت `mrw-bot-keepalive.timer` يعمل كل 5 دقائق تلقائيًا (منصّب مع المشروع) |

**لماذا الـ keepalive مهم؟** Oracle قد تستعيد (reclaim) النسخ المجانية الخاملة إذا انخفض استهلاك المعالج تحت 10% والشبكة تحت 20% لمدة 7 أيام. المؤقّت يرفع متوسط الاستهلاك بأمان — بلا أي تأثير على عمل البوت.

## ⚠️ مشكلات شائعة وحلولها

| المشكلة | السبب | الحل |
|---------|-------|-----|
| `Out of capacity` عند الإنشاء | لا توجد سعة في المنطقة/الشكل | جرّب شكلًا آخر، أو منطقة أخرى (المنطقة الرئيسية غير قابلة للتغيير بعد إنشاء الحساب)، أو أعد المحاولة بعد ساعات |
| `Connection timed out` | قواعد جدار حماية VCN لا تسمح بـ 22 | Networking → VCN → Security Lists → Add Ingress Rule: TCP 22 من 0.0.0.0/0 |
| `UNPROTECTED PRIVATE KEY FILE` | صلاحيات ملف المفتح في ويندوز | `icacls` (أعلاه) |
| `409 Conflict` في سجلات البوت | نسختان من البوت تقرآن التحديثات | أوقف النسخة المحلية (أعلاه) |
| `systemctl restart` يعيد التشغيل فورًا | خطأ في الإعدادات | `journalctl -u mrw-bot -n 30` لرؤية سبب التوقف |
| توكن غير صالح | خطأ في نسخ التوكن | تأكد من عدم وجود مسافات في `.env` |

## 🔐 ملاحظات أمنية

1. **جلسة حسابك الشخصي (`user_session.session`) لا تُرفع إلى الخادم** — سكربت النشر يستثنيها عمدًا. إدارة البوتات تتم من جهازك فقط.
2. **الوصول للخادم بمفتاح SSH فقط** — لا كلمة مرور ولا مستخدمون آخرون.
3. **الملف `.env` بصلاحية 600** — لا يقرأه إلا مالكه.
4. **UFW مفتوح على SSH فقط** — لا خدمات إنترنت مكشوفة (البوت يخرج إلى تلغرام، ولا يحتاج أحد أن يدخل).
5. إن صار النظام حساسًا جدًا: **Oracle ليست بيئة مناسبة للسرية القصوى** — بياناتك عند مزوّد خارجي. البديل: خادم داخلي في القسم. كثير من الجهات تستخدم Oracle لأدوات إدارية غير حرجة، وهذا مقبول تقنيًا — لكن **الأدلة والصور**: يُفضَّل أن تبقى نسخة على جهاز القسم الداخلي، والأصل على السحابة.
