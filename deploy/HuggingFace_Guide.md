# دليل Hugging Face Spaces — المسار المجاني الدائم (ZeroGPU)

> ⚠️ **تحديث مهم (2026/10/22):** سياسة Hugging Face تغيّرت.
> حسب التوثيق الرسمي الحالي: إنشاء **Gradio أو Docker Space** يتطلب خطة **PRO ($9/شهر)**،
> والحساب الشخصي المجاني يبقى قادرًا على تشغيل **مساحتين من نوع ZeroGPU فقط**، وبشرطين:
> **1) تفعيل البريد الإلكتروني، 2) عمر الحساب 30 يومًا على الأقل.**
> بعد استيفاء الشرطين تكون المساحة مجانية **للأبد** (حصة 5 دقائق GPU يوميًا — ولا نحتاج GPU أصلًا).
>
> **الخطة العملية:** الحساب **القديم** يفي شرط الـ30 يومًا → المساحة المجانية متاحة **فورًا**.
> نشر البوت داخل المساحة عبر `space_app.py` (جاهز مسبقًا).
> والبديل الفوري الآخر: **Zeabur** (`deploy/Zeabur_Guide.md`).

## 1) المتطلبات

- حساب **Hugging Face** مجاني: <https://huggingface.co/join>
- حساب **GitHub** (لرفع الكود): <https://github.com/join>
- قناة تيليغرام خاصة (القناة الرسمية)

## 2) التحقق من حساب Hugging Face (لديك حساب قديم)

بما أن الحساب قديم، فالأمر الوحيد المتبقي هو **تفعيل البريد** (شرط إلزامي):

1. سجّل الدخول: <https://huggingface.co/login>
2. اذهب إلى **Settings → Profile** (أو **Account**) وتحقق من أن البريد بجانب اسمك
   يظهر كمُفعّل (لا توجد علامة تحذير).
   - إن لم يكن البريد مُفعّلًا: ستجد في البريد رسالة تفعيل من Hugging Face — افتحها واضغط الرابط.
   - إن لم تجد رسالة تفعيل: في صفحة الملف الشخصي اختر **Add a new email**، أو من
     <https://huggingface.co/settings/tokens> أعد إرسال رسالة التأكيد.
3. من **Settings** لاحظ **اسم المستخدم** (يظهر في رابط المساحة:
   `https://<اسم-المستخدم>-mrw-bot.hf.space`).
4. تأكد أن الحساب ليس عليه تحذير (banner) من نوع "Your account is not in good standing".

> **لا تطلب المنصة بطاقة بنكية** في أي خطوة.
> ✅ بهذا يصبح الحساب مؤهّلًا لاستضافة **مساحتين ZeroGPU مجانًا للأبد**.

## 3) تجهيز الكود للنشر

المساحة المجانية من نوع **Gradio**، لذلك نستخدم غلافًا جاهزًا: `space_app.py`
(يشغّل البوت في خيط خلفي ويعرض صفحة حالة بسيطة).

في جذر المشروع:
- `space_app.py` — غلاف Gradio (موجود ✅)
- `requirements-space.txt` — مكتبات المساحة (موجود ✅)
- `Dockerfile` — بديل لمنصة أخرى (Zeabur)، غير مطلوب هنا

ادفع الكود إلى مستودع GitHub **خاص**:

```powershell
git init
git add .
git commit -m "نظام استقبال بلاغات المخالفات العسكرية"
git branch -M main
git remote add origin https://github.com/<اسم-حسابك>/mrw-bot.git
git push -u origin main
```

> **الأمان:** ملف `.gitignore` المرفق يستثني `data/` و`media/` و`logs/` و`.env` و`*.session`،
> فلا يُرفع أي توكن ولا صورة بلاغ ولا قاعدة بيانات.

## 4) إنشاء المساحة

1. من <https://huggingface.co/spaces> اضغط **Create new Space**.
2. اختر:
   - **Space name**: `mrw-bot`
   - **Space SDK**: **Gradio**
   - **Visibility**: **Private** (بياناتك لا تُعرض لأحد)
3. اضغط **Create Space**.
4. **مهم — اختيار العتاد:** بعد إنشاء المساحة اذهب إلى **Settings ← Hardware**
   واختر **ZeroGPU** من القائمة (توثيق HF: "Make sure the ZeroGPU hardware is selected
   in your Space settings"). المساحة المجانية يقبل عتاد ZeroGPU فقط.

> **مسار رابط المساحة بعد النشر:** `https://<اسم-المستخدم>-mrw-bot.hf.space`

---

## 5) رفع الكود

من صفحة المساحة: تبويب **Files and versions** ← **Add file** ← **Upload files**، وارفع:

```
space_app.py
main.py  config.py  texts.py  handlers.py  admin.py  database.py
keyboards.py  utils.py  exporters.py  archive.py  health_server.py
requirements-space.txt
```

> **مهم:** ملف `README.md` في جذر المساحة هو بطاقة المساحة، ويجب أن يحتوي ترويسة YAML
> (انسخه جاهزًا من `deploy/huggingface/README.md`).

## 6) ضبط الأسرار

من **Settings** ← **Variables and secrets** ← **New secret**:

| الاسم | القيمة |
|---|---|
| `BOT_TOKEN` | توكن البوت من BotFather |
| `ADMIN_IDS` | `1557513643` |
| `ARCHIVE_CHAT_ID` | معرّف القناة الرسمية |
| `SAVE_MEDIA_LOCALLY` | `0` |
| `BACKUP_INTERVAL_MIN` | `30` |
| `KEEPALIVE_INTERVAL_SEC` | `300` |
| `KEEPALIVE_URL` | رابط المساحة: `https://<اسم-المستخدم>-mrw-bot.hf.space` |
| `LOCAL_UTC_OFFSET` | `3` |
| `BOT_USERNAME` | `@blgh_bot` (للعرض في صفحة الحالة) |

ثم **Restart** من أعلى الصفحة.

---

## 7) القناة الرسمية

1. في تلغرام: **New Channel** (قناة **Private**).
2. إعدادات القناة ← **Administrators** ← أضف `@blgh_bot` مشرفًا بصلاحية **Post Messages** و **Read Messages**.
3. انشر أي رسالة داخل القناة، ثم أرسل `/chatid` للبوت — سيردّ بمعرّف المحادثة.
4. انسخ المعرّف (يبدأ بـ ‎-100‎) وضعه في `ARCHIVE_CHAT_ID`.

## 8) الاختبار

- تبويب **Logs**: تأكد من `✅ البوت جاهز…` و `📁 القناة الرسمية جاهزة…`.
- أرسل بلاغًا تجريبيًا من حساب آخر وتأكد من وصوله للمشرف + القناة.
- أعد تشغيل المساحة (Restart) وتأكد من استعادة قاعدة البيانات من القناة.

## 9) المراقب الخارجي (ضروري لمنع النوم التلقائي)

> ⚠️ **نقطة جوهرية:** النبضة داخل البوت (`KEEPALIVE_URL`) لا تنفع إذا أوقفت المنصة
> الحاوية نفسها، لأن البوت يكون متوقفًا ولا يستطيع أن يطلب شيئًا.
> لذلك نحتاج **مراقبًا خارجيًا** يطلب رابط المساحة كل 10 دقائق، فيوقظها إن نامت.

الحل الجاهز في المشروع: `.github/workflows/keepalive.yml`

**الخطوات:**

1. أنشئ مستودع GitHub (يمكن أن يكون خاصًا) ودفع إليه الكود — فيعمل ملف المراقب تلقائيًا.
2. من المستودع: **Settings ← Secrets and variables ← Actions ← New repository secret**:

   | الاسم | القيمة |
   |---|---|
   | `SERVICE_URL` | `https://<اسم-المستخدم>-mrw-bot.hf.space` |
   | `BOT_TOKEN` | توكن البوت (اختياري — لإرسال تنبيه عند التعطّل) |
   | `ADMIN_IDS` | `1557513643` (اختياري) |

3. من تبويب **Actions** تأكد أن سير العمل `keepalive` ظاهر ويمكن تشغيله يدويًا
   (**Run workflow**) للاختبار.

**التكلفة:** المستودع العام = دقائق بلا حد، والخاص ≈ 1440 دقيقة شهريًا (ضمن الحد المجاني 2000).

**ماذا يحدث إن نامت المساحة؟** يستيقظها المراقب خلال 10 دقائق كحد أقصى، ويصلها ما رُحّل
في طابور تلغرام (24 ساعة) وتُعالَج فورًا.
