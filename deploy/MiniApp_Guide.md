# دليل تطبيق البلاغ (Mini App داخل تلغرام)

تطبيق ويب صغير يعمل **داخل تلغرام** (Mini App) فيملأ المبلِّغ البيانات بسرعة:
نوع المخالفة، الموقع تلقائيًا، الصورة، الوصف، ورابط المنشور — ثم تصل إلى البوت
ويُسجَّل بلاغًا كاملًا كإرسال عادي.

---

## 0) كيف يعمل (بكل بساطة)

```
التطبيق (في الهاتف)  ──sendData──▶  البوت  ──▶  قاعدة البيانات + لوحة المشرف + القناة
        (النوع، الموقع، الوصف، الرابط)
                                   └──▶ يطلب الصورة في المحادثة ← يُكمل البلاغ
```

**لماذا هكذا؟** لأن `sendData()` في تيليغرام محدود بـ **4096 بايت** — لا يمكن إرسال
الصورة عبرها. لذلك يبقى الصورة في المسار الطبيعي (تلغرام) حيث تُحفظ إلى الأبد،
وتصل البيانات المنظّمة من التطبيق.

---

## 1) النشر — **من داخل مساحة Hugging Face** (بلا GitHub)

التطبيق يُقدَّم من المساحة نفسها عبر خادم FastAPI بسيط:

| المسار | المحتوى |
|---|---|
| `/` | تطبيق البلاغ (Mini App) — **هذا هو رابط التطبيق** |
| `/api/public/vtypes` | تصنيفات البلاغ وحدود الإدخال الفعلية من قاعدة بيانات البوت (قراءة عامة بلا أسرار) |
| `/api/app-data` | استقبال بيانات البلاغ بعد التحقق من توقيع Telegram |
| `/status` | صفحة حالة بسيطة (HTML خفيف) |
| `/health` | فحص آلي: `{"status": "ok", ...}` |

### كيف صُنِّعت البنية؟

```
المساحة (HF Space — Gradio SDK)
   └── space_app.py
         ├── خيط خلفي  → البوت (يستقبل البلاغات)
         └── خادم FastAPI/uvicorn على PORT
                ├── "/"        → ملفات webapp/ (التطبيق)
                ├── "/api/public/vtypes" → التصنيفات والحدود الفعلية
                ├── "/api/app-data"     → استقبال البيانات الموقّعة
                ├── "/status"  → صفحة الحالة
                └── "/health"  → فحص المنصة
```

> **لماذا لم نُبقِ Gradio؟** لأن وكيل Gradio (Node) يعترض كل المسارات على نفس المنفذ
> ويخدم صفحته هو، فلا يبقى مكان لتطبيقنا. لذلك استُبدل بخادم مباشر + صفحة حالة بسيطة.

> **تقرير إقلاع ZeroGPU:** شرط لتشغيل أي مساحة ZeroGPU (وإلا أوقفتها المنصة برسالة
> `No @spaces.GPU function detected`). نُرسله يدويًا في `_zerogpu_startup_report()`
> لأننا لا نمرّ على مسار إقلاع Gradio الرسمي.

### التحقق من النشر

```powershell
$env:HF_TOKEN='hf_...'
$env:HF_SPACE='azzam1992/mrw-bot'
.\.venv\Scripts\python.exe deploy\deploy_to_hf.py `
  --bot-token '<BOT_TOKEN>' `
  --admin-ids '1557513643' `
  --keepalive-url 'https://azzam1992-mrw-bot.hf.space' `
  --mini-app-url 'https://azzam1992-mrw-bot.hf.space/'
```

ثم من صفحة المساحة ← **Logs** تأكّد من ظهور:

### شرط أساسي: المساحة يجب أن تكون **عامة**

لأن تلغرام يفتح التطبيق من داخل المحادثة بلا مصادقة → المساحة الخاصة تردّ 404.
(الخصوصية محفوظة: الكود بلا سرّ، والأسرار في HF Secrets.)

## 2) بعد التفعيل — ماذا يتغيّر؟

| المكان | التغيير |
|---|---|
| **كل مستخدم** | يظهر زر «🚀» بجوار مربع الكتابة يفتح التطبيق |
| **الترحيب** | رسالة ترحيب محدّثة تشرح النطاق الرسمي + رابط المنشور الإلزامي + تحذير الدقة |
| **الأمر `/app`** | يفتح التطبيق مباشرة (وينفع أيضًا بلا زر) |
| **البلاغ من التطبيق** | يُسجَّل مع: `source=app` + `violation_type` + `place` + `latitude/longitude` + `platform` |
| **العرض في لوحة المشرف** | يظهر رقم البلاغ التسلسلي ونوع المخالفة والمنصة والموقع |

تُحمّل قائمة التصنيفات وحدود الوصف والصورة من البوت عند فتح التطبيق، لذلك تتزامن
مع إعدادات الإدارة بدل قائمة ثابتة في المتصفح. إذا لم يستطع التطبيق تحميلها
يعرض خطأ ويمنع بدء نموذج غير متصل بتصنيفات صالحة. يتحقق الخادم كذلك من أن
التصنيف المختار ما زال ضمن القائمة الفعلية، ويرفض الوصف الطويل بدل اقتطاعه.
فحوص الرابط والمضمون والتكرار موحدة بين إدخال المحادثة وMini App؛ ويُحال
التكرار أو مصدر النشر غير المعروف إلى المراجعة اليدوية.

## 3) الاختبار قبل الاعتماد

| # | الخطوة | المتوقع |
|---|---|---|
| 1 | افتح التطبيق من زر القائمة | شاشة البداية بثلاث خطوات |
| 2 | اختر نوعًا + اضغط «تحديد موقعي» | ✅ يظهر الإحداثيات |
| 3 | التقط صورة + اكتب وصفًا | تظهر المعاينة |
| 4 | **احذف الرابط ثم اضغط «مراجعة»** | يظهر تنبيه «رابط المنشور إلزامي» |
| 5 | ضع رابط تيك توك حقيقي | ✅ «تم التعرّف على منصة النشر: تيك توك» |
| 6 | اضغط «إرسال البلاغ» | يعود البوت: «وصلت بياناتك» + «أرسل الصورة» |
| 7 | أرسل الصورة في المحادثة | يصلك رقم `MRV-YYYY-NNNN` |
| 8 | افتح `/admin` | البلاغ موجود مع النوع والمنصة والموقع |

## 4) التشغيل المحلي

لا يكفي خادم ملفات ثابت مثل `python -m http.server` لتجربة النموذج؛ إذ يجب أن
يكون مسار التصنيفات الديناميكي متاحًا من خدمة البوت. افتح تطبيق البلاغ من رابط
الخدمة بعد تشغيلها. خارج Telegram لا تتوفر بيانات `initData` الموقعة، لذلك
لا يمكن استخدام مسار استقبال الخادم أو ضمان إنشاء البلاغ عبر المشاركة.

---

## 5) إذا لم يعمل التطبيق

| العَرَض | السبب المحتمل | الحل |
|---|---|---|
| الزر لا يفتح شيئًا | `MINI_APP_URL` غير مضبوط | اضبطه ثم Restart |
| «تعذّر قراءة بيانات التطبيق» | صيغة JSON غير صحيحة | أعد الإرسال من التطبيق |
| لا يصل شيء بعد الإرسال | التطبيق أُرسل خارج تلغرام | افتحه من داخل تيليغرام |
| الرابط مرفوض | رابط غير http/https أو نطاق محجوب | صحّح الرابط |
| «تعذّر تحديد الموقع» | إذن الموقع مرفوض أو غير متاح | اكتب وصف المكان يدويًا |

## 6) فحص الصور وتجميد الحسابات آليًا

```powershell
python -m pip install -r requirements.txt
$env:NSFW_SCREENING_ENABLED = "1"
$env:NSFW_SCREENING_THRESHOLD = "0.85"
$env:NSFW_REVIEW_THRESHOLD = "0.40"
```

يعمل NudeNet محليًا عبر ONNX، ويفحص الصورة الأصلية ثم حتى أربع قصاصات متداخلة
للصور الكبيرة لتحسين التقاط التفاصيل الصغيرة. الكشف عالي الثقة (0.85 افتراضيًا)
للأعضاء التناسلية أو الشرج يؤدي إلى حظر دائم حتى رفعه يدويًا؛ الكشف الأضعف
(0.40 فأعلى)، ومؤشرات الثدي أو الأرداف وتعذر الفحص تُحال للمراجعة البشرية ولا
تؤدي وحدها إلى الحظر. يُسجّل الحظر الآلي في سجل التدقيق ويصل تنبيه نصي للمشرف
من دون إرفاق الصورة.

المصنّف احتمالي وقد يخطئ أو يفوّت صورًا، ولا يحدد العمر أو السياق؛ لا توجد أداة
مجانية تضمن كشف كل الصور. تبقى الصور على خادم البوت ولا تُرسل لخدمة خارجية.
قد تتطلب القصاصات الإضافية وقت معالجة أطول للصور الكبيرة.
