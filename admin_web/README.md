# لوحة الإدارة — Flutter Web وAndroid

لوحة تحكم كاملة لبوت بلاغات المخالفات العسكرية، مبنية بـ Flutter وتعمل على الويب
وAndroid وتتصل بـ API الإدارة الحي على خادم البوت نفسه.

## الروابط

- **على Render:** `https://mrw-bot.onrender.com/admin/`
- **محليًا (سطح المكتب):** شغّل `launch_desktop.bat` من جذر المشروع.
- **Android:** ابنِ APK وفق الخطوات أدناه وثبّته يدويًا على الهاتف.

## الدخول

تُفتح اللوحة على شاشة توكن الإدارة. التوكن هو قيمة `ADMIN_API_TOKEN` في `.env`
وعلى Render. يُخزَّن في متصفحك فقط (`localStorage`).

يستطيع المالك إضافة حسابات من صفحة «المشرفون والصلاحيات» واختيار دور وصلاحيات كل حساب.
تُعرض الرموز الجديدة مرة واحدة، وتُحفظ بصمتها فقط في قاعدة البيانات. تدوير رمز
المالك يبطل الرموز القديمة (بما فيها رموز البيئة)؛ احفظ الرمز الجديد قبل إغلاق
نافذة عرضه.

## البناء

```powershell
cd admin_web
.\build_release.ps1
```

السكربت:

1. ينشئ رقم إصدار بتاريخ اليوم (`2.7.YYYYMMDD`).
2. يبني Flutter Web بـ `--base-href=/admin/`.
3. يمرّر الإصدار عبر `--dart-define=APP_VERSION=...`.
4. ينسخ المخرجات إلى `dist/` (المجلد الذي يخدمه خادم البوت).
5. يزيد رقمًا فرعيًا إذا تكرر بناء إصدار في اليوم نفسه.

أضف ملخص الإصدار وميزاته إلى أعلى قائمة `releaseNotes` في
`lib/release_notes.dart` عند تجهيز كل إصدار؛ تعرض صفحة «ما الجديد» السجل
بالإصدارات وتُبرز الإصدار المثبت.

للاتصال بخادم مختلف وقت البناء:

```powershell
$env:API_BASE = "https://example.com"
.\build_release.ps1
```

بدون `API_BASE` تستخدم اللوحة نفس منبع الصفحة (وهو المطلوب على Render).

## بناء تطبيق Android

تحتاج Flutter SDK وAndroid SDK مع تراخيص Android مقبولة. من مجلد `admin_web`:

```powershell
flutter pub get
flutter build apk --release
```

ملف التثبيت الناتج:
`build/app/outputs/flutter-apk/app-release.apk`

يستخدم التطبيق معرّف Android الثابت `com.abuazzam.mrwbot.admin` ويطلب Android 6
(API 23) أو أحدث للتخزين الآمن. يوقّع البناء المحلي بإعداد توقيع debug الافتراضي؛
لذلك يصلح للتثبيت اليدوي والاختبار، وليس للنشر عبر متجر التطبيقات. يُقبل كتحديث
فوق الإصدار المثبت من الجهاز نفسه ما دامت شهادة Android debug المحلية لم تُحذف.
قبل توزيع التطبيق على أجهزة أخرى أو إضافة تحديث داخلي، يجب إعداد مفتاح إصدار
خاص ثابت وعدم استخدام مفتاح debug.

تغييرات اللوحة المبنية للويب لا تُحدّث APK المثبت تلقائيًا. بعد تعديل التطبيق،
أعد بناء APK وثبّته على الهاتف؛ وقد يحتاج Android إلى تأكيد التحديث. أما تغييرات
الخادم وحده فتصل دون إعادة بناء التطبيق.

من «الإعدادات ← تطبيق الهاتف» يستطيع المالك إيقاف التطبيق مؤقتًا أو دائمًا،
ونشر إصدار اختياري أو إلزامي بإدخال رابط HTTPS مباشر وبصمة SHA-256. يفحص APK
السياسة عند التشغيل وأثناء الاستخدام، وينزّل الملف إلى مساحة التطبيق الخاصة،
ويتحقق من البصمة قبل فتح مُثبّت Android الرسمي؛ يتطلب التثبيت موافقة المستخدم
وسماح Android بالتثبيت من هذا التطبيق. يجب أن يكون رابط التنزيل مباشرًا، وأن
يُوقّع APK الجديد بمفتاح الإصدار نفسه المستخدم في النسخة المثبتة، مع زيادة
`versionName` في `pubspec.yaml`. لا يرفع التطبيق APK إلى الخادم.

بعد بناء APK ارفع الملف إلى استضافة HTTPS عامة مباشرة، ثم احسب بصمته في
PowerShell بالأمر:

```powershell
Get-FileHash .\build\app\outputs\flutter-apk\app-release.apk -Algorithm SHA256
```

## الثيمات

أربعة أوضاع داكنة من زر لوحة الألوان في شريط التطبيق:

- الغابة الداكنة (افتراضي)
- منتصف الليل
- المحيط
- الجرافيت

الاختيار محفوظ في `localStorage` لكل متصفح، واللون الأخضر `#67D6A6` يبقى
موحّدًا في كل الأوضاع.

## نظام التصميم ومكونات الواجهة

- `lib/design_tokens.dart`: قياسات مشتركة للمسافات وأنصاف أقطار البطاقات والعناصر.
- `lib/app_theme.dart`: ألوان السمات، الخط العربي، والأنماط العامة للأزرار والبطاقات والتنقل.
- `lib/widgets.dart`: مكونات مشتركة مثل `SectionCard`؛ يمكنها عرض عنوان فرعي وأيقونة وإجراء.
- `lib/admin_shell.dart`: شريط التطبيق والتنقل المتجاوب؛ يعرض أسماء الأقسام عند التوسيع، ويقلل ازدحام الشريط على العرض المتوسط.
- تستخدم النظرة العامة هذه المكونات المشتركة؛ تُضاف تحسينات الصفحات الأخرى تدريجيًا دون تغيير عقود الـ API.
