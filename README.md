# نظام استقبال بلاغات المخالفات العسكرية (Telegram Bot)

نظام متكامل ومؤمّن لاستقبال بلاغات المخالفات العسكرية عبر بوت تلغرام، مع لوحة إدارة للمشرف وتصدير التقارير إلى Excel أو ملف نصي منظم.

- **لوحة Flutter:** واجهة إدارة محلية تتصل بخدمة API فعلية، وتتطلب عنوانًا صالحًا وتوكن إدارة؛ البيانات الوهمية محصورة في الاختبارات.
- **اللغة:** Python 3.10+ (تم اختباره على Python 3.14)
- **المكتبات:** `python-telegram-bot` (v22)، `SQLite` للتطوير المحلي أو Turso في الإنتاج، `pandas` + `openpyxl` للتصدير، `python-dotenv` للإعدادات.

---

## 📁 هيكل المشروع

| الملف         | الوظيفة |
|---------------|---------|
| `main.py`     | نقطة التشغيل: تجميع الوحدات، السجلات (Logs)، بدء الاستقبال |
| `config.py`   | الإعدادات المركزية: التوكن، معرفات المشرفين، حدود التشغيل (يقرأ `.env`) |
| `database.py` | طبقة البيانات: SQLite محليًا وTurso على Render، مع تهيئة الجداول والفهارس وفحوص الاتصال |
| `handlers.py` | محادثة المستخدم: الترحيب ← صورة ← رابط ← وصف ← تأكيد ← الحفظ |
| `admin.py`    | لوحة المشرف: قوائم، إدارة الحالات، التصدير، الإحصائيات |
| `keyboards.py`| بناء أزرار المستخدم والمشرف |
| `texts.py`    | كل نصوص البوت بالعربية (تُعدّل من مكان واحد) |
| `exporters.py`| توليد Excel منسق + ملف نصي منظم |
| `utils.py`    | التوقيت المحلي، التحقق من الروابط، حماية HTML |
| `archive.py`  | القناة الرسمية الموحّدة + نسخ قاعدة البيانات احتياطيًا عبر تلغرام (طبقة ثانية اختيارية) |
| `hub_backup.py`| النسخ الاحتياطي السحابي الأساسي: مستودع Dataset خاص على Hugging Face + استعادة تلقائية عند الإقلاع |
| `health_server.py` | خادم صحة HTTP بسيط لازم منصات الاستضافة السحابية |
| `_selftest.py`| اختبار ذاتي سريع بدون تلغرام (اختَر: `python _selftest.py`) |

مجلدات تُنشأ تلقائيًا: `data/` (قاعدة البيانات)، `media/` (الصور)، `exports/` (التقارير)، `logs/` (السجلات).

## ⚙️ خطوات التثبيت والتشغيل (ويندوز)

### 1) إنشاء بوت والحصول على التوكن
1. في تلغرام، ابحث عن **@BotFather**.
2. أرسل: `/newbot` ثم اختر اسمًا واسم مستخدم ينتهي بـ `bot`.
3. سيمنحك **توكن** مثل: `1234567890:AAE3...xYz` — احفظه.

### 2) معرفك كمشرف (Admin ID)
1. ابحث في تلغرام عن **@userinfobot** وأرسل له أي رسالة.
2. سيعطيك **Id** رقمي — انسخه.

### 3) تجهيز ملف الإعدادات
انسخ الملف `.env.example` وأعد تسميته إلى `.env`، ثم عدّله:

```env
BOT_TOKEN=1234567890:AAE3...xYz      # التوكن من BotFather
ADMIN_IDS=123456789                   # معرفك الرقمي (يمكن وضع أكثر من واحد بفاصلة)
LOCAL_UTC_OFFSET=3                    # توقيت مكة/الرياض/صنعاء
```

> ⛔ ملف `.env` سرّي: لا ترسله لأحد ولا ترفعه لإنترنت.

### 4) إنشاء البيئة الافتراضية وتثبيت المكتبات
افتح **PowerShell** داخل مجلد المشروع:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

> إذا ظهر خطأ "تعطيل تشغيل السكربتات" نفّذ مرة واحدة:
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ثم أعد التنشيط.

### 5) فحص ذاتي (اختياري لكن مفيد)

```powershell
python _selftest.py
```

ينبغي أن يظهر في النهاية: `=== كل الاختبارات نجحت ✅ ===`

### 6) تشغيل البوت

```powershell
python main.py
```

ستظهر رسالة `✅ البوت جاهز ويستقبل الرسائل …` — افتح بوتك في تلغرام وأرسل `/start`.
لإيقافه: `Ctrl + C`.

## ☁️ الاستضافة والنسخ الاحتياطي

| المسار | الحالة | الدليل |
|---|---|---|
| **خدمة Render** | `https://mrw-bot.onrender.com`؛ آخر نشر مؤكد `b496847eabe21df0612f453299508fbefbc8df34` | `/version` مطابق؛ `/admin/` و`/db-health` وصحة Turso أعادت نجاحًا |
| **Hugging Face Space** | عنوان افتراضي اختياري في اللوحة؛ أعاد `/health` و`/api/admin/overview` حالة 404 عند الفحص | ليس عنوان الخدمة الفعلية الحالية |
| **Hugging Face Dataset** | مخزن النسخ الاحتياطية | `hub_backup.py` |

يستطيع `space_app.py` تقديم API الإدارة، كما يدعم `main.py` تشغيله عند وجود
متغير `PORT`. تتطلب تهيئة Turso على Render ضبط `DB_BACKEND=turso` و
`TURSO_DATABASE_URL` و`TURSO_AUTH_TOKEN` في مخزن أسرار Render. ينشئ التطبيق
الجداول والفهارس ويطبق ترحيلات قاعدة البيانات عند بدء التشغيل، ويتيح
`/db-health` فحص اتصال القاعدة. خارج Render يكون SQLite هو الافتراضي للتطوير؛
على Render يُرفض بدء التشغيل مع SQLite أو عند غياب إعدادات Turso. قاعدة الإنتاج
`mrw-bot` في `aws-eu-west-1`؛ راجع `PROJECT_HANDOFF.md` لبصمة النشر ونتائج الفحص.

**النسخ الاحتياطي:**

في وضع SQLite المحلي، يمكن استخدام النسخ الاحتياطي إلى Dataset خاص على Hugging Face
(`hub_backup.py`) أو القناة الرسمية (`archive.py`). عند اختيار Turso، يتجاوز التطبيق
استعادة ونسخ ملفات SQLite؛ تعتمد استمرارية البيانات على قاعدة Turso.

1. **النسخ الاحتياطي لSQLite المحلي — مستودع Dataset خاص على Hugging Face** (`hub_backup.py`):
   بحسب إعدادات بيئة الخدمة، تُرفع لقطة متسقة دوريًا إلى مستودع Dataset الخاص:
   - `latest/reports.db` — النسخة الحالية (يُستبدل بالاسم نفسه في كل رفعة).
   - `daily/YYYY-MM-DD/reports.db` — لقطة مؤرَّخة واحدة كل يوم.
   - تاريخ المستودع يُصفَّر تلقائيًا كل 30 يومًا (وفق حدود المنصة).
   **الاستعادة عند الإقلاع**: إذا وُجدت قاعدة الخدمة فارغة (حاوية جديدة
   مسحها السحابي) يجلب البوت آخر نسخة تلقائيًا — ولا يستبدل أبدًا قاعدة
   محلية تحتوي بيانات.
2. **الطبقة الثانية (اختيارية) — القناة الرسمية في تلغرام** (`archive.py`):
   عند ضبط `ARCHIVE_CHAT_ID` تُنشر البلاغات ونسخ القاعدة في القناة أيضًا.

عند إعداد استضافة فعلية مستقبلًا، تُضبط متغيرات البيئة السرية من مخزن أسرار
الاستضافة، ولا تُضاف إلى الملفات أو المستودع. تتضمن أسماء الإعدادات التي
يستهلكها التطبيق:

```env
BOT_TOKEN=...            # توكن البوت
ADMIN_IDS=1557513643     # معرف المشرف
HF_TOKEN=...             # سرّ النسخ الاحتياطي (اختياري بحسب الإعداد)
ADMIN_API_TOKEN=...      # سرّ واجهة المشرف
ADMIN_API_TOKENS_JSON=... # رموز بأدوار منفصلة (اختياري)
SAVE_MEDIA_LOCALLY=0     # في الاستضافة: نعتمد على file_id في تلغرام
BACKUP_INTERVAL_MIN=30   # فترة النسخ الاحتياطي بالدقائق
DB_BACKEND=turso        # Render: إلزامي؛ التطوير المحلي: sqlite
TURSO_DATABASE_URL=...  # سرّ/عنوان قاعدة Turso
TURSO_AUTH_TOKEN=...    # سرّ قاعدة Turso، لا تضعه في Git
```

> معرّف القناة الرسمية يُعرف بالأمر `/chatid` من داخل القناة بعد إضافة البوت مشرفًا فيها.

## 🖥 تشغيل لوحة Flutter على سطح المكتب

1. ثبّت Flutter على Windows وأضفه إلى `PATH`.
2. شغّل `launch_desktop.bat` من مجلد المشروع.
3. يفتح المتصفح اللوحة على `http://127.0.0.1:9000/`. أدخل توكن الإدارة الحالي عند شاشة الاتصال؛ لا تضع توكن البوت أو مفاتيح الاستضافة في اللوحة.

هذا المشغّل يبني ملفات Flutter ويخدمها محليًا فقط. تظهر شاشة الاتصال بعنوان API
قابل للتعديل، افتراضيًا `https://azzam1992-mrw-bot.hf.space`؛ يمكن تغييره قبل
التشغيل بتعيين `ADMIN_API_BASE_URL`. لا تُضمّن أسرارًا في هذا المتغير.

شاشة الدخول تتصل بالخدمة الحقيقية فقط ولا تعرض خيار دخول تدريبي. يلزم إدخال
عنوان API الفعلي وتوكن إدارة صالحين؛ عنوان Hugging Face الموجود افتراضيًا مجرد
إعداد اختياري، وقد لا تكون الواجهة متاحة عليه.

تشمل لوحة الإدارة أقسام النظرة العامة والبلاغات والمبلّغين والتشغيل والرسائل
والتصنيفات والتدقيق والمحجوبين والتحليلات وسلامة النظام، إضافة إلى تفضيلات
الخط وحجم النص والكثافة ولون التمييز. يدعم سير البلاغات الأولوية والإسناد وموعد
المتابعة، مع مؤشرات للعاجل والمتأخر وغير المسند. يمكن طلب معلومات من المتبلّغ
وتلقي رده عبر Telegram. تعدّل صفحة التشغيل حدود المستخدم في الدقيقة والساعة
واليوم وحدود الإغراق العامة، وعتبة ومدد التجميد التصاعدية، ورسائل التنبيه
والحظر اليدوي. يمكن إيقاف حدود المستخدم أو التجميد تلقائيًا لمدة محدودة (5
دقائق إلى 24 ساعة) مع سبب إلزامي؛ يبقى حد الإغراق العام والإيقاف الطارئ فعالين،
ولا يرفع الإيقاف المؤقت حظرًا يدويًا أو ساريًا. تُحفظ الإعدادات في قاعدة
البيانات وتطبق فورًا على البوت. تفضيلات التصميم محلية للمتصفح.

تُفرض صلاحيات API على الخادم بحسب الرمز: `viewer` للقراءة، `reviewer` لمراجعة
البلاغات، `operator` للإجراءات التشغيلية والإدارة، و`owner` لجميع الصلاحيات.
يدعم `ADMIN_API_TOKENS_JSON` رموزًا بأدوار منفصلة، ويمكن إبقاء
`ADMIN_API_TOKEN` رمز مالك واحدًا. لا تُخزّن الرموز في الواجهة أو المستودع؛
أضفها إلى مخزن أسرار الخدمة فقط.

لملخص التسليم، حالة العمل المحلية، خريطة الملفات، تعليمات التحقق والتوصيات،
راجع [`PROJECT_HANDOFF.md`](PROJECT_HANDOFF.md).

## 👤 استخدام المبلّغ

1. `/start` → رسالة ترحيب تشرح العناصر المطلوبة.
2. أرسل **الصورة التوثيقية** (صورة عادية أو ملف صورة بحد 10MB).
3. أرسل **رابط المنشور** (يجب أن يبدأ بـ http/https).
4. اكتب **وصفًا موجزًا** (حتى 1500 حرف).
5. راجع الملخص ثم اضغط **✅ إرسال البلاغ**.
6. يصلك **رقم بلاغ فريد** (مثل `MRV-2026-0001`) وتحت المراجعة بحالة "جديد 🟡".
7. الحد الابتدائي **10 بلاغات يوميًا**؛ يمكن للمالك تعديله من صفحة التشغيل.
8. في أي وقت: زر **❌ إلغاء** أو `/cancel`.
9. إذا طلبت الإدارة معلومات إضافية، أرسل `/reply رقم_البلاغ النص` في المحادثة الخاصة مع البوت.

## 🛡 استخدام المشرف

- `/admin` أو `/reports` — المحمية بمعرفك من `ADMIN_IDS` (غيرك يرى رسالة رفض).
- **🆕 البلاغات الجديدة** — قائمة مع ترقيم صفحات؛ اضغط رقم البلاغ لعرضه:
  - تظهر التفاصيل كاملة مع **الصورة**.
  - تغيير الحالة: 🟡 جديد / 🟠 قيد المراجعة / 🟢 معتمد / 🔴 مرفوض. سبب الرفض إلزامي ويُرسل للمبلّغ برسالة.
- **📥 تصدير Excel** — ملف `.xlsx` اتجاهه يمين-يسار، بعناوين ملونة، **حالة كل بلاغ**، عدد البلاغات لكل حالة، الصورة جانبًا، رابط قابل للنقر.
- **⛔ المحجوبون** — قائمة بالحجب الساري تشمل المستخدمين بلا بلاغات، وتعرض السبب والمدة، مع رفع الحجب أو مراسلة المستخدم عبر البوت.
- **📄 تصدير نصي** — ملف `.txt` مقسم بفواصل ومنظم ومعد للتقديم.
- **📊 إحصائيات** — الجملة الكلية، بحسب الحالات، وعدد آخر 24 ساعة.
- يصلك **إشعار فوري** عند كل بلاغ جديد (الصورة + الملخص).

## 🔒 الملحوظات الأمنية

- أسرار التطوير محليًا في `.env` المستثنى من Git، وأسرار الخدمة في مخزنها؛ لا تضمّنها في الواجهة أو الكود.
- كل أزرار/أوامر المشرف تتحقق من هوية الضاغط (وليس مجرد الرسالة).
- تحقق صارم من الروابط (http/https فقط) وحد أقصى لحجم الصورة والوصف.
- كل نص المستخدم يُمرّر عبر تشفير HTML قبل إمكانية التمثيل في أي رسالة (منع حقن الطبقات العليا/العلامات).
- حماية ملف Excel من ** حقن الصيغ ** (`= + - @` تُعالج كنص).
- حد يومي لكل مبلّغ ضد إغراق النظام بالرسائل.
- سجل كامل مع دوّار ملفات في `logs/bot.log`.

## 💾 النسخ الاحتياطي

**في وضع السحابة (المعتمد):** البوت يرفع نسخة من قاعدة البيانات داخل القناة الرسمية تلقائيًا (بعد كل بلاغ + كل 30 دقيقة)، ويستعيد آخر نسخة عند كل إقلاع — فلا تفقد البيانات حتى لو أُعيد بناء الخادم.

**في الوضع المحلي:** أوقف البوت (`Ctrl+C`) ثم انسخ:

```
data/reports.db  + مجلد media/ كاملًا
```

> ملف قاعدة البيانات `reports.db` هو كل شيء — أعد وضعه مع مجلد الصور في أي جهاز وسيعود النظام كما كان.
